# Installing SGLang

This is a guide based on the [official installation instructions](https://docs.sglang.ai/start/install.html). It is recommended to use [`uv`](https://github.com/astral-sh/uv) as the Python package manager for faster installation.

```bash
pip install --upgrade pip
pip install uv
uv pip install "sglang[all]>=0.4.10.post2"
```

## Installing with Docker

This is the recommended way to install SGLang, as it provides a consistent environment and allows you to use the latest features.

```bash
# Clone the SGLang repository
git clone https://github.com/sgl-project/sglang.git
cd sglang/docker

# Build the docker image
docker build -t sglang-cpu:main -f Dockerfile.xeon .

# Initiate a docker container
docker run \
    -it \
    --privileged \
    --ipc=host \
    --network=host \
    -v /dev/shm:/dev/shm \
    -v ~/.cache/huggingface:/root/.cache/huggingface \
    -p 30000:30000 \
    -e "HF_TOKEN=<secret>" \
    sglang-cpu:main /bin/bash
```

## Deploying on Kubernetes

Running SGLang on Kubernetes provides scalability, high availability, and resource management benefits for production workloads. The containerized nature of SGLang makes it well-suited for Kubernetes deployment.

### Basic Kubernetes Deployment

Here's a basic deployment manifest for SGLang:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: sglang-deployment
  labels:
    app: sglang
spec:
  replicas: 1
  selector:
    matchLabels:
      app: sglang
  template:
    metadata:
      labels:
        app: sglang
    spec:
      containers:
      - name: sglang
        image: sglang-cpu:main
        ports:
        - containerPort: 30000
        env:
        - name: HF_TOKEN
          valueFrom:
            secretKeyRef:
              name: huggingface-secret
              key: token
        resources:
          requests:
            memory: "8Gi"
            cpu: "4"
          limits:
            memory: "16Gi"
            cpu: "8"
        volumeMounts:
        - name: model-cache
          mountPath: /root/.cache/huggingface
        - name: shm
          mountPath: /dev/shm
      volumes:
      - name: model-cache
        persistentVolumeClaim:
          claimName: model-cache-pvc
      - name: shm
        emptyDir:
          medium: Memory
          sizeLimit: 2Gi
---
apiVersion: v1
kind: Service
metadata:
  name: sglang-service
spec:
  selector:
    app: sglang
  ports:
  - protocol: TCP
    port: 80
    targetPort: 30000
  type: LoadBalancer
```

### GPU-Enabled Deployment

For GPU workloads, you'll need to configure GPU resources and node selectors:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: sglang-gpu-deployment
  labels:
    app: sglang-gpu
spec:
  replicas: 1
  selector:
    matchLabels:
      app: sglang-gpu
  template:
    metadata:
      labels:
        app: sglang-gpu
    spec:
      nodeSelector:
        accelerator: nvidia-tesla-v100
      containers:
      - name: sglang
        image: sglang-gpu:latest
        ports:
        - containerPort: 30000
        env:
        - name: CUDA_VISIBLE_DEVICES
          value: "0"
        - name: HF_TOKEN
          valueFrom:
            secretKeyRef:
              name: huggingface-secret
              key: token
        resources:
          requests:
            memory: "16Gi"
            cpu: "8"
            nvidia.com/gpu: 1
          limits:
            memory: "32Gi"
            cpu: "16"
            nvidia.com/gpu: 1
        volumeMounts:
        - name: model-cache
          mountPath: /root/.cache/huggingface
        - name: shm
          mountPath: /dev/shm
      volumes:
      - name: model-cache
        persistentVolumeClaim:
          claimName: model-cache-pvc
      - name: shm
        emptyDir:
          medium: Memory
          sizeLimit: 8Gi
```

### Persistent Volume Configuration

Create a persistent volume claim for model caching to improve startup times:

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: model-cache-pvc
spec:
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 100Gi
  storageClassName: fast-ssd
```

### Secrets Configuration

Store your Hugging Face token securely using Kubernetes secrets:

```bash
kubectl create secret generic huggingface-secret \
  --from-literal=token=your_huggingface_token_here
```

### Horizontal Pod Autoscaler

For dynamic scaling based on CPU utilization:

```yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: sglang-hpa
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: sglang-deployment
  minReplicas: 1
  maxReplicas: 10
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 70
```

### Production Considerations

When deploying SGLang in production on Kubernetes, consider the following:

**Resource Requirements**: SGLang can be memory-intensive, especially when loading large models. Plan for adequate memory allocation with a typical requirement of 8-32 GB RAM depending on model size. GPU deployments may require 16-80 GB VRAM for larger models.

**Model Caching Strategy**: Use persistent volumes to cache downloaded models, reducing startup time from minutes to seconds. Consider using a shared filesystem like NFS or distributed storage for multi-pod access to the same models.

**Network Configuration**: Configure appropriate ingress controllers and load balancers to handle external traffic. Consider using service mesh technologies like Istio for advanced traffic management and observability.

**Monitoring and Observability**: Implement comprehensive monitoring using Prometheus and Grafana to track model performance, request latency, and resource utilization. Set up alerts for memory pressure, GPU utilization, and response time degradation.

**Security**: Use Pod Security Standards to enforce security policies, implement network policies to restrict inter-pod communication, and regularly update container images to address security vulnerabilities.

The time complexity for model loading is **O(n)** where n is the model size, while inference time complexity varies by model architecture but is typically **O(s·d)** where s is sequence length and d is model dimension. Space complexity is **O(m + c)** where m is model parameters and c is context cache size.

### Helm Chart Deployment

For simplified Kubernetes deployments, you can create a Helm chart. Here's a basic `values.yaml` configuration:

```yaml
# values.yaml
replicaCount: 1

image:
  repository: sglang-cpu
  tag: main
  pullPolicy: IfNotPresent

service:
  type: LoadBalancer
  port: 80
  targetPort: 30000

resources:
  requests:
    memory: "8Gi"
    cpu: "4"
  limits:
    memory: "16Gi"
    cpu: "8"

# GPU configuration
gpu:
  enabled: false
  count: 1
  nodeSelector:
    accelerator: nvidia-tesla-v100

# Model caching
persistence:
  enabled: true
  size: 100Gi
  storageClass: fast-ssd

# Hugging Face configuration
huggingface:
  token: ""  # Set via --set huggingface.token=your_token

# Autoscaling
autoscaling:
  enabled: false
  minReplicas: 1
  maxReplicas: 10
  targetCPUUtilizationPercentage: 70

# Monitoring
monitoring:
  enabled: false
  serviceMonitor:
    enabled: false
```

Deploy using Helm:

```bash
# Install the chart
helm install sglang ./sglang-chart \
  --set huggingface.token=your_huggingface_token \
  --set gpu.enabled=true

# Upgrade deployment
helm upgrade sglang ./sglang-chart \
  --set replicaCount=3 \
  --set autoscaling.enabled=true
```
